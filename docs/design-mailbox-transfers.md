# Export and import of a mailbox in the admin web

The administrator asked for a button (2026-11-22). The rule of the admin web stays: **it has no access to mail**. So it asks, and the service that holds the mailboxes does the work, and the file passes through the database in pieces.

* **Who.** Platform administrators only. Every request is in the audit log; the download, which is a read, is written by hand (and refused with `503` when the audit row cannot be written: mail is not handed over without the record). The pieces of an upload are not recorded one by one (hundreds of rows); the import is, when it is started.
* **Tables** (migration 0046): `mailbox_transfers` (kind, account, who asked, state, counts, a fixed word for a failure, times) and `mailbox_transfer_chunks`. Everything is removed 24 hours after it was asked for (the garbage collector). Grants: the admin role reads and writes these two tables and nothing of the mailbox; the IMAP role updates the transfer and writes the pieces of an export.
* **Export** (`POST /api/v1/accounts/{a}/exports`): the IMAP service (`TransferService`, which polls the table; no job queue, so no new rights on `jobs`) reads every folder and writes one mbox into 4 MiB pieces, each message marked `X-Rusty-Folder`, with `Status` and `X-Status` flags and the date of its `From ` line. `GET /api/v1/transfers/{t}/download` streams the pieces. At most 256 MiB.
* **Import** (`POST .../imports` with an optional folder, then `PUT /api/v1/transfers/{t}/chunks/{n}`, then `POST /api/v1/transfers/{t}/start`): the server takes at most 64 KiB in a request, so the browser cuts the file into pieces of 48 KiB (at most 64 MiB in all). A piece is sent as raw bytes but with `Content-Type: application/json`, because the guard against forged requests asks that of every change; it is not read as JSON. The import starts only when every piece up to the count it names has arrived and none beyond. The worker files each message in the folder its header names (made when missing), else the folder chosen, else the Inbox, with its date and flags. The mailbox's quota applies: when it is full the import stops and says `quota`; a message that cannot be stored is counted as skipped; a file that holds no message fails as `unreadable`.
* **Failures are words**, never text from the file: `quota`, `too_large`, `unreadable`, `not_found`, `failed`. A transfer left `running` for an hour by a worker that stopped is marked failed.
* **The page.** The Mailbox button of an account row (platform administrators): export, import of a file (with the folder for messages that do not say), the list of the last day with a download link, refreshed while something is being done.

The same file format and the same functions are used by `rustyctl mailbox` (docs/design-mailbox-tools.md); the format lives in `rusty_core::mbox`.
