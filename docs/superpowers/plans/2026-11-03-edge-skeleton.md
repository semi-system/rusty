**Goal:** Build the hardened public entry container (Traefik) with static file configuration, plus a Compose skeleton with fake backends and an automated check that proves the hardening rules, so real services can be dropped in later.

**Architecture:** One `edge` container (Traefik, digest-pinned, read-only, no capabilities, file provider only) is the only container that publishes ports. Certificates for HTTPS and for the implicit-TLS mail ports (465 SMTPS, 993 IMAPS, 995 POP3S) are obtained and renewed automatically by the separate `certd` service (Go, lego/certmagic; see the tenant TLS spec) and handed to Traefik as files (file provider only, NO `certificatesResolvers` — user decision 2026-11-03 supersedes the earlier Traefik-resolver design); the edge terminates TLS there and re-encrypts with mTLS to backends (user decision; trade-off recorded in spec §3b.1). Port 25 and the optional STARTTLS ports (587, 143, 110; disabled by default per RFC 8314) are TCP passthrough with PROXY protocol v2. Fake backends are tiny static Rust binaries built in this repo (no third-party images except Traefik).

**Tech Stack:** Docker/Compose (rootless where possible), Traefik v3 (resolve the latest stable tag, then pin by digest), Pebble + challtestsrv (Let's Encrypt's official test ACME server; pin by digest) for tests, Rust (backends, checker, tests), rustls.

**Spec:** `docs/superpowers/specs/2026-11-03-rusty-container-deployment-design.md` §3b (edge), §4 (hardening), §5 (transports), §10 (tests).

## Global Constraints

- Only the `edge` service may publish ports; no service mounts a container-runtime socket; no `privileged`, no host networking; every service: non-root uid, `read_only: true`, `cap_drop: [ALL]` (edge adds only `NET_BIND_SERVICE` if it must bind < 1024), `no-new-privileges`, memory/cpu/pids limits, healthcheck.
- Traefik: file provider only (read-only mount), Docker provider and every provider needing a runtime socket disabled, API/dashboard not reachable from outside (disabled or on the internal admin network only), no plugins, access log in JSON without query strings or auth headers.
- TLS min 1.2 (prefer 1.3); PROXY protocol v2 to TCP backends; trusted-IP lists explicit; HTTP forwarded headers trusted only from edge.
- ACME: explicit hostname allowlist (never issue for arbitrary SNI); production CA only via an explicit non-test configuration flag, tests and dev ALWAYS use Pebble/staging; ACME storage file 0600 on a volume mounted only into `edge`; DNS-01 credentials only as a 0400 secret file, scoped token; no key material in images, env vars, logs or the repo; TLS >= 1.2 (prefer 1.3) with one shared `tls.options` for HTTP and TCP routers; mail ports 587/143/110 disabled by default.
- If the pinned Traefik version cannot do TLS to a TCP backend together with PROXY protocol v2, STOP and report; do not silently fall back to plaintext (spec §3b.5).
- Images pinned by digest in `deploy/images.lock` (script prints and verifies digests; build fails on mismatch). The Traefik version is resolved at implementation time from the official image and recorded with its release date; do not invent a version.
- Secrets (test certificates) are generated by a script into an untracked directory with mode 0400/0700; nothing secret is committed.
- All checks runnable offline after images are pulled; the check script exits non-zero on the first violation and prints which rule failed.

## Review Focus

- A compose file in which ANY service other than `edge` publishes a port, mounts `/var/run/docker.sock`, is `privileged`, uses `network_mode: host`, or runs as root must fail the checker (negative tests with deliberately bad fixtures).
- PROXY protocol spoofing: a client sending its own PROXY header through the edge must not be able to forge the source IP seen by a backend.
- Passthrough must not alter bytes (binary round-trip, STARTTLS upgrade through the edge).
- Dashboard/API exposure, default routers, and catch-all routes must not leak backend names or let unknown `Host` values reach internal services.
- ACME abuse and failure: SNI outside the allowlist must not trigger issuance; CA outage must not take down serving of existing certificates; a lost/corrupt ACME store must not serve broken certificates; key material must never appear in logs or `docker inspect` output.
- Resource exhaustion at the edge (many idle connections, slowloris, oversized headers/bodies) is bounded by configured limits and proven with tests.
