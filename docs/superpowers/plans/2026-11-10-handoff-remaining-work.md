## 1. What Rusty is, in five lines
Security-first Rust remake of Zimbra FOSS (mail + groupware). Standard protocols only (IMAP/SMTP now; JMAP/CalDAV/CardDAV later) plus a Zimbra import tool later. Cargo workspace, `#![forbid(unsafe_code)]`, musl static binary. **Postgres is the production backend** (user decision 2026-11-09, so no SQLite->Postgres data migration is ever needed); SQLite stays as the dev/test backend and the conformance reference; message bodies are content-addressed files on a volume. Current priority (user): **usable first, performance/hardening later, but never break the architecture model for speed**.

## 3. How to work here (hard rules; CI enforces most of them)
- Edit on Windows paths under `<repo>*`; **build/test only through WSL helpers** run from the worktree root: `bash scripts/wsl-cargo.sh <cargo args>` and `bash scripts/wsl-ci.sh` (full gate; log `~/rusty-ci.log` in WSL, shared by all runs: only ONE full CI at a time - check `pgrep -af scripts/ci.sh`). No `python`. WSL `/tmp` is wiped; keep logs in `$HOME`. cargo target dir lives on ext4 (`$HOME/rusty-target`, use another dir per worktree if the script allows).
- The WSL VM shuts down when no `wsl.exe` session is alive (`uptime` says 0 min): a CI run dies, target dirs can corrupt (zero-length rlibs, incremental ICE: wipe the target dir / `cargo clean --target x86_64-unknown-linux-musl`). `<home>\.wslconfig` has `vmIdleTimeout=-1` (applies after the next VM restart); keep a background `wsl.exe -e sleep 43000` session open as a belt-and-braces keepalive.
- Postgres tests: per-run container via `scripts/pg-lib.sh` (`RUSTY_PG_RUN_ID`), always tear down your own (`scripts/pg-down.sh`), never touch others' `rusty-pg-test-*` containers. `RUSTY_REQUIRE_PG=1` makes missing PG a failure.
- Git: small commits, conventional messages (`feat(imap): ...`), **never push**, never rewrite history, one worktree/branch per task (`git worktree add -b <branch> <repo><x> main`), the user (or Claude) merges. Do not commit the uncommitted edit to `docs/superpowers/plans/2026-11-03-postgres-backend.md` if you still see it in a tree.
- TDD: write the test, SHOW it failing for the stated reason, then implement. Concurrency/security tests must be shown to catch a mutation (scratch edit, run, `git checkout`, tree clean).
- Gates that every new crate/test must satisfy with NO exemptions: clippy `-D warnings`; `cargo-deny` + `cargo-audit` (new crate = licence check, no AGPL, no OpenSSL, ignore list only with written reason - see RUSTSEC-2026-0459 entry); `scripts/check-raw-db.sh` (no raw pool/SQL outside `rusty-store`); `check-service-crates.sh` (service crates use only repository facades: `Directory::with_repo`, `Mailbox::open_with`, ...); `check-parametrised.sh` (every DB test runs on BOTH backends via `for_each_backend` or carries a specific `backend-neutral: <reason>`); `check-test-knobs.sh`/`check-test-fixtures.sh`/`check-mutation-hook.sh` (test-only features never reach release); `check-wrapped-libs.sh` + `scripts/wrapped-libs.txt` (third-party protocol libs only inside an `adapter` module, Rusty-owned types in every `pub` signature); `check-pg-migration-gap.sh`; fuzz targets for every parser we own (cargo-fuzz in `fuzz/`, seeds committed, smoke in CI); musl release build and static-link check.
- Architecture invariants (master plan section 1b, binding): protocol servers talk ONLY to repository traits/facades; one crate per protocol with codec separated from session logic separated from I/O (sans-I/O, wire-level library-independent tests); constructor injection, no globals; domain = tenant isolation, DB clock for correctness columns, mailbox row locked first then blobs in ascending hash order, SQLSTATE-only error mapping (`Error::Busy` -> SMTP 451 / IMAP `NO [UNAVAILABLE]`), no session state in SQL (PgBouncer-ready: no session advisory locks, `SET` -> `SET LOCAL`); deferred features keep a SEAM (trait/hook/config key), never a structural shortcut.
- Security floor even in "usable first": TLS-only auth, Argon2 hashes, parser limits, no panics on input, fail closed, no secrets in logs/Debug/errors, key files 0600.
- Review policy: strong independent review for parser/auth/concurrency/tenant isolation; light elsewhere. If you cannot get an independent reviewer, add a written self-review section to your PR notes listing attacks you tried.

## 5. Known open issues (from strong reviews, not yet fixed unless noted)
- Whole-blob FETCH: header-only folder sync reads every byte of a mailbox; chunked attachment download re-parses the whole message per chunk (needs ranged `BlobStore` reads).
- No global in-flight memory budget in IMAP unless the `u-imap` reconciliation landed `MemoryBudget` use; SMTP has `MemoryBudget` (config `[limits] inflight_message_mib`, default 1024); each message is copied ~4 times (streaming to the blob store is the real fix, deferred).
- `postmaster@` cannot be delivered in a domain with no active account (documented limitation).
- Submission/inbound limiters are in-memory per process (seams exist: `SubmissionLimiter`, `RateLimiter`); U5 makes the outbound enqueue caps persistent.
- Flaky-under-load pre-existing tests: `query_shape` statement-count probes are process-global; `rusty-directory` 10k acceptance (default limit now 150 s); quickstart smoke port collisions (W4).
- GC singleton is a local-volume file lock (not safe on NFS/multi-host; planned: lease row with epoch); `PgStore::connect` migrates on connect (fixed by W5).
- Deferred on purpose (each has a seam): edge/HAProxy in front, `store` as a separate service, KMS, ACME/certd, rspamd/ClamAV (`InboundFilter`), webmail/JMAP, ACL sharing, quota enforcement, PgBouncer (plan task PG8a), benchmark at 100,000 mailboxes / 1M mails/day (PG7), sharding by mailbox.
- Bundled SQLite advisory RUSTSEC-2026-0459 is ignored with an expiry (revisit on each sqlx release, no later than 2027-02-01); acceptable because production data is on Postgres.
